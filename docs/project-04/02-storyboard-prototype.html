Screen Flow Storyboard & UI Paper Prototype

IGB100 · Team 8 · Feb–May 2025 · Team paper-prototyping pass, before any screen was built in Unity

Before building any UI in Unity, the team mapped the entire screen flow and sketched every menu on paper. This let us argue about structure — what triggers the shop, what the pause menu replaces, what a game-over screen needs to show — without spending implementation time on screens that might get reshuffled.

Full Screen-Flow Storyboard

Two branch points were deliberately numbered on the sketch: from Gameplay, either the player survives all waves (1, → Result screen) or HP hits 0 (2, → Game Over); from the Result or Game Over screen, the player can return to the Main Menu.

Individual Screen Sketches

Comparing these sketches against the final in-engine shop and level-up screens (in the Scrum Progress Reports) shows how closely the shipped Cycle 2 prototype tracked this original paper pass — the priced-slot shop layout and the multi-choice level-up screen both survived into the final build largely unchanged.
